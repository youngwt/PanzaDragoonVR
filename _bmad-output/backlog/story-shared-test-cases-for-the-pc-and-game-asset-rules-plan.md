## Intent

**Problem:** `tools/manifest.py` and the game's `AssetManifest`/`GlbCheck` implement the same asset contract separately, with separate hand-written tests, and they disagree. `write_manifest.py --check` passes models the game rejects, accepts `NaN`, `Infinity` and deeply nested manifests the game cannot read, reads a lone surrogate differently, and words the same problem differently. A folder that passes on the PC can fall back to placeholders on the headset (retrospective R1, R2, V1, A-dup).

**Approach:** One set of test cases on disk (manifest folders, each with its expected result) that both test suites run, and `tools/manifest.py` brought into line with the game wherever the two share a rule. The game is the reference: its rules and wording are the ones players see on the launch report.

## Boundaries & Constraints

**Always:**
- Python standard library only in `tools/`; the C# tests keep no Godot reference.
- Fixture files are generated by a committed script and are the author's own: no disc data.
- Rules only the PC checks stay as they are: `sha256` format and value, `meta`'s type, a missing `manifest.json` as a problem, write mode's scan of files.
- The contract stays the authority; a case where the game itself breaks the contract stops the work for the author.

**Never:**
- No change to the game's behaviour, rules or wording.
- No change to the asset contract.
- No symbolic links in the shared cases (they cannot be committed portably); those tests stay in each suite.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Good folder | Two images and the test model | No problem on either side | No error expected |
| Model the game rejects | External or `data:` URI, `extensionsRequired`, wrong length, no mesh, bad glTF version | `--check` and write mode report it in the game's words | Nothing written |
| Unreadable manifest | `NaN`, `Infinity`, nesting deeper than 64, not JSON | Both say the manifest is not valid JSON | Parser detail text may differ |
| Lone surrogate | In `id`, `path`, `kind` | Same outcome as the game: invalid entry for `id`/`path`, unknown kind for `kind` | As the game |
| Shared entry rules | Absent or wrong fields, bad ID, bad path, leaving the folder, missing, not a file, wrong size, not an 8-bit RGB/RGBA PNG, duplicate ID | The same problem lines on both sides | As the game |

## Code Map

- `tools/manifest.py` -- `check_report` (236-356) and `contents_problem` (79-98) hold the PC checks; `build` (139-224) is write mode and uses `contents_problem`. Model check is header-only (91-97). `json.loads` at 255.

- `game/Logic/LaunchReport.cs` `Build` -- how the game merges `AssetManifest.Problems` with each lookup's problem, skipping repeats; the C# side of the shared runner does the same, looking up each entry with its own kind when the kind is `image` or `model`.
- `tests/tools/test_manifest.py`, `tests/tools/test_make_test_model.py` -- `unittest`, imports `tools/` via `sys.path`. `tests/GameLogic.Tests/` -- xUnit; tests find files relative to the repo.

- `tools/test.sh` -- runs Python discovery in `tests/tools`, then `dotnet test`.

## Implementation Notes

- 42 cases. Beyond the matrix: `nested-64-deep` (readable) against `unreadable-nested-65-deep`, which pins the game's depth limit; `several-problems`, which pins the order (entry problems first, then file problems in manifest order); `model-no-node-uses-a-mesh`, `model-gltf-version-1`, `model-not-a-glb`; and several path rules split one per case.
- `check_report` now groups as the game does: pass 1 mirrors `ReadEntries`/`EntryProblem` (one `invalid entry:` line per entry, reasons joined by `; `; a duplicate drops every entry with that ID); pass 2 mirrors `Find` on the usable entries. A size mismatch is the only line for that file, as in `Find`. Absent or mistyped top-level fields are now one line joined by `; `, as the game's `Unreadable` reason.
- PC-only rules kept: `sha256` format (now checked on every entry) and value (after the size check), `meta` type, missing manifest, file checks on unknown kinds. The `unsupported format` line keeps the PC's own wording ("this tool understands"); it is outside the matrix and the game's line names "this build".
- `glb_problem` ports `GlbCheck.Check` in order and words, including the paths that throw in C# (a lone surrogate in a string the check reads, a non-number `byteLength`, a non-object buffer) as "the JSON chunk could not be read". Not decoded: images inside the model, as in `GlbCheck`.
- `contents_problem` now returns the game's text after `<id>: <path>: ` (`unreadable image: …` or a model-table line); write mode prefixes the ID and path.
- The C# runner reads entry IDs and kinds from the manifest itself, since `AssetManifest` does not expose kinds; no game code changed.

## Review Triage Log

Quick lens, 2026-10-16: high 0, medium 0, low 5, false 0, maybe-false 0. One patched, four rejected.

- low, patched: a `tools/README.md` sentence made the game the reference wherever it and the contract disagree, against this plan's boundary. It now limits the game's role to wording between the two implementations, and sends a game-against-contract case to the author.
- low, rejected: a non-string entry in a model's `extensionsRequired` is shown re-serialised by Python (`{"a": 1}`) where the game shows the raw JSON (`{"a":1}`). This is rare, and matching it needs a raw-text JSON reader in Python.
- low, rejected: shortening a long `uri` can split a two-unit UTF-16 character differently on the two sides. Rare, and a fiddly fix for one character on the board.
- low, rejected: `bytes` written as `-0` with a size mismatch reads "says -0" in the game and "says 0" in Python. Rare, and Python cannot see the raw number text.
- low, rejected: Python calls a special file (FIFO, device) "not a file" where the game would go on to check its size. Rare in an asset folder, and following the game would make Python read from a FIFO, which can hang.

## Design Notes

- **Cases on disk, not generated at test time.** Both suites then read the same bytes; a generator in each language would be one more pair to keep in step. The script that writes them is committed, so a case is changed by editing the script and re-running it.
- **The game wins on wording.** Its lines are what players read on the board; `--check` is the author's preview of that board.
